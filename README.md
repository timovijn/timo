# timo

A native, local-first iPhone daily planner built with SwiftUI. Requires iOS 26 or later and a compatible Xcode installation. There are no third-party dependencies, accounts or network requests.

## Run on your iPhone

1. Open **Timo.xcodeproj** in Xcode (not Package.swift).
2. Select the **Timo** project in the left sidebar, then the **Timo** application target.
3. Under **Signing & Capabilities**, leave **Automatically manage signing** enabled and select your **Personal Team**. If the bundle identifier is unavailable, change `com.timovijn.timo` to a unique identifier.
4. Connect your unlocked iPhone, trust the Mac and enable Developer Mode if prompted.
5. Select your iPhone as the destination beside the Timo scheme and press **⌘R**.

A free Personal Team can install the app on your phone. You must run it again from Xcode when its seven-day provisioning profile expires. Keep the same bundle identifier and update the installed app rather than deleting it to preserve its local data.

## Run in Simulator

Open the same project, select an installed iPhone Simulator as the destination and press **⌘R**. No signing team is needed for Simulator. If a runtime is missing, install it through Xcode Settings → Components.

Tapping anywhere outside a text field, or opening a schedule or reminder popover, also closes the keyboard; the tap still reaches whatever it landed on. The Schedule section is one line of inline capsule buttons: the day, **Add time**, and, once a time is set, **+ End**. The day reads Today, Tomorrow, Yesterday or a weekday within the coming week, otherwise a short date; its popover offers Today / Tomorrow / Next week above a calendar and closes on a choice. Schedule popovers always open below their button (arrow on top) at a fixed width, so the calendar is never squeezed beside the leftmost button. **Add time** picks a start after the day’s last timed item and not before now (rounded up to a quarter hour; the next whole hour today when nothing else is planned; otherwise 9:00) and opens a popover with that suggestion, 9:00, 12:00 and 18:00 above a time wheel. **+ End** opens duration choices (15m, 30m, 45m, 1h, 2h) on one evenly divided line (wrapping only at large text sizes; VoiceOver reads full durations) above an exact end date and time. A duration sets the end time and leaves the popover open so the end can be checked or fine-tuned. The button shows the end time itself: “until 10:30”, or “until Saturday, 10:30” on a later day; and the end can only be after the start. Set times carry an ✘ inside the capsule (with a 44-point tap target); removing the start also removes the end, but the duration is remembered while the editor is open and comes back when a time is added again. Buttons animate in and out (immediately under Reduce Motion), adding or removing a value gives a selection haptic, and the capsules wrap at large text sizes. VoiceOver reads them as Day, Time and End time with full values (for example “Ends 29 Oct 2026 at 11:00, 1 hour”), Add time / Add end time, and Remove time / Remove end time. There is no Task/Event selector.
- Schedule and reminder pickers open in a popover below their button. If the button is low on the screen, the form first scrolls it up so a tall calendar is never cut off.
- Add one or more reminders in the item editor's **Reminders** section, which uses the same inline buttons as the schedule, tinted blue so reminders stand out; **+ Reminder** itself is a neutral grey button like **+ End**. The first reminder asks for notification permission. Reminders are stored as a list; plans saved with the earlier single reminder load as a one-item list. A blue alarm button filters the selected day to unfinished items with an upcoming reminder; tap again to return. Filter buttons use separate circular glass controls with small orange/blue count badges. They fade and gently scale in and out over 0.32 seconds within one persistent toolbar host; the remaining control shifts smoothly into place. Reduce Motion uses a short fade without scaling. Active filters use tinted native Liquid Glass with coloured icons; inactive controls are neutral. The bottom add and view-mode buttons use primary-colour icons. Filter icons are lighter and medium-weight, with a softer tint when active. The blue and orange filters are mutually exclusive. Both filtered views share the same status-and-action panel below each item: a small coloured symbol, a caption and a tinted action bar. Reminder status shows a blue alarm and the next upcoming reminder (or the latest past one), including its date when different from the viewed day, plus “· N reminders” when there are several; warning status shows an orange warning symbol and its reason. Reminder actions are Complete, Change time and Remove. ## Personas

Personas are the different focuses in a life: **Health**, **Work**, **Family**, **Friends** and **Personal**. Each has its own gradient orb (mint–green, cyan–blue, yellow–orange, pink–red, purple–indigo).

- The glass capsule in the top left shows the current persona with its orb. It starts on **All**, a blend of every persona's colour, which is the normal day view.
- Tap the capsule to open the persona menu, which grows out of it as a Liquid Glass list: All, Health, Work, Family, Friends and Personal, each with its orb and a checkmark on the current one. Choose one to switch to it. VoiceOver reads the capsule as "Persona" with the current choice; the menu is the system one, so it reads naturally too.
- Switching persona cross-fades: the day view and the persona pages fade into each other, so each page's gradient wash blends into the next rather than sliding across. The capsule's label changes at once, and the menu folding back into it is the only motion. There is no swiping between personas; horizontal swipes on the day view still change the day.
- Choosing a persona swaps the day view for that persona's history: every item in that persona grouped by day, newest day first (Tomorrow, Today, Yesterday, then weekday and date), under a small "x/y complete" line like the day view's. The page doesn't repeat the persona's name or orb; instead the top-left button's glass takes on the persona's colour while one is chosen, the same light tint the review and reminder filter buttons show when they're on. The tint switches at once with the label, so it never lingers after going back to All. The day view stays loaded underneath, so going back to All returns to the same day instantly. The review and reminder filters rest while a persona is shown, because they belong to a single day.
- In the history, tap a circle to complete an item or tap the item to edit it. **+** adds an item for today that already has the persona.
- The item editor keeps its explanations out of the way: each section title (Persona, Repeat, Carry over, Reminders, and Schedule for a carried item) has a small (i) that shows or hides that section's explanation, which appears beneath the section's content. They start hidden.
- In the item editor, the **Persona** section offers None plus the five personas, each with its orb. The chosen chip reads like a reminder pill in the persona's colour: a light tint of that colour with the name in it. A chosen None takes a darker grey, and the unchosen chips stay quiet with grey text. A persona is optional, and None is the default for items added from the day view.
- A carried-over item is listed once, on the day it is shown as itself (today, or the day it was completed), with its "Carried from" line. A repeating item shares one persona across all its occurrences. Its history lists the occurrences up to today (with a repeat symbol) but not the future ones generated ahead, so they don't bury the history. Non-repeating items planned for later days are listed.
- The set of personas is fixed for now. Adding, renaming or recolouring them is not built yet.

## Scheduling decisions

- One item model with a local day, optional start time, optional end time, completion and an independent carry-over preference. There is no stored task/event type in the new format.
- Calendar.current determines local days, including across daylight-saving transitions.
- An item's scheduled day never changes on its own. An unfinished item with carry-over enabled is shown on today as an untimed item with a "Carried from" line, until it is completed; its scheduled day and time stay as planned. A time range that is still running stays on its own day until it ends.
- Ticking an item off while viewing a past day records it as done on that day (at the current time of day). A carried item completed that way is shown completed on that day and no longer on the days after it, so an event added after the fact can be ticked off on the day it actually happened. Ticked off on today or a future day, it counts as done now.
- Where an item is shown is worked out from its scheduled day, its completion and the current time, so nothing has to run at midnight; the view follows the day as it changes.
- Items with carry-over disabled, completed items and future items are shown on their scheduled day only. Repeating occurrences never carry.
- Every day from a carried item's scheduled day up to the day it is shown on keeps a quiet "Carried to …" entry. These entries are not counted, reviewed or reminded about again; ticking one off completes the item on that day.
- Rescheduling an item moves its trail with it: planned for a later day, the earlier days let it go. Plans saved before this (when carrying moved an item's day to today) are restored to their scheduled day once on opening, with time ranges shifted back; a single time that was dropped when it moved cannot be recovered.
- Past days otherwise contain the items still scheduled there, not a snapshot of the original plan. No historical copies are generated.
- Time ranges appear on every day they overlap; ending at midnight excludes the following day.
- Changing a start time or day preserves an existing duration. Removing the start time also removes the end time.
- Stored parent relationships are preserved, but linking controls and parent completion suggestions are temporarily disabled in the interface.
- Time-passed suggestions never change completion state. Leave open dismisses the suggestion until the schedule changes or completion is undone. A carried item is not flagged for its old time.
- Parent selection enforces one level of linked children and rejects missing parents and cycles.
- The screen follows today across midnight when viewing today; intentionally viewing another day does not jump back.

## Persistence

The plan is stored as an atomically written, versioned JSON document in the app's Application Support/Timo/plan.json. The plan is small and local; this keeps version one dependency-free and allows scheduling tests to run without an iOS runtime. SwiftData is not used in this implementation. A later storage migration can retain the existing item IDs.

The version 6 format adds an optional persona to each item (and to repeat templates). It reads existing version 1–5 plans without changing item IDs or schedules; their items open without a persona. A persona this version doesn't know also reads as none. Repeat templates were added in version 5. Legacy tasks default to carry-over enabled and legacy events to disabled. The next successful write saves the new format.

Writes complete before in-memory state is published. Save failures are surfaced. An unreadable or unsupported existing document is left untouched and saving is disabled. Deleting the app deletes its local plan. There is no backup/export UI yet.

## Reminders

Local notifications are scheduled after a successful save and refreshed at launch or foreground entry. Completion, deletion, disabling a reminder and time edits update pending notifications; notifications also present while the app is open. Notification delivery must still be checked on the iPhone, including permissions and Focus settings.

The nearest 64 future reminders are scheduled, replenished on subsequent saves or app entry. Reminders that have passed are never repeated for a carried item. Each reminder is its own notification. Changing an existing start shifts all its reminders by the same amount; changing an untimed item's day shifts them by calendar days. Removing an item's start preserves its explicitly set reminders.

## Tests

From the project folder:

```sh
swift test
```

Package.swift contains the Foundation-only scheduling model and XCTest suite. The app compiles the same model source directly. Tests cover missed days, repeated reconciliation, local midnight and daylight-saving transitions, events/completed/future tasks, parent links, overnight visibility, validation, deletion choices, completion suggestions, rescheduling and JSON/file persistence.

Command-line application build without signing:

```sh
xcodebuild -project Timo.xcodeproj -scheme Timo \
  -destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO build
```
